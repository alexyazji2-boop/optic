## 14. Performance and recovery: complete and verified, bottlenecks listed (39b5fad)
Measured first, on this Mac against :8076, desktop and a throttled phone (150 ms round trip, 1.6 Mbps down, 4x CPU), with `perf_check.py` (full load and in-app navigation per route, every API request and repeats) and `perf_repeat.py` (40 route changes, then a 20 s freeze and resume). Full numbers: `~/Optic/work/v2-backlog/perf-before/`, `perf-cold/`, `perf-cold-after2/`, `perf-repeat/`, `perf-repeat2/`.

**What the measurements found**
- No request is fetched twice on any of 13 routes, desktop or phone (one repeat of `/api/session` on Home was the top bar's one-minute refresh).
- Warm visits (the browser has the scripts): 0.1 to 1.0 s on desktop, 0.8 to 2.7 s on the throttled phone; in-app navigation 0.02 to 0.6 s. These are data-bound (the Dossier's snapshot is about 120 KB).
- A first visit (empty browser cache) on the throttled phone took 4.5 to 5.4 s, and downloaded all 80 modules (about 600 KB) whatever the page: the page preloaded every module.
- Memory: 40 route changes grew the document from 13,973 to 75,297 nodes and listeners from 182 to 1,249. Every page with a chart stayed in memory: the chart module kept each mounted chart slot, and dropped detached ones only on a window resize.

**What changed**
- Pages load when first opened (`app.js`, dynamic `import()`); the first load preloads only the shell's static graph (32 modules), and the import map still names every module, so a page fetched later resolves to the same versioned file. Opening a page asks for its own modules side by side (`v2-graph` in index.html, from `frontend.static_graph`) rather than one import at a time; a later route wins a race; a failed fetch says so with Try again. Four seconds after the first page draws, the likeliest next pages are fetched without running (not on Save-Data or 2G).
- `mountCharts` drops slots of pages already left.

**Measured after (cold, throttled phone):** Home 4.47 to 3.02 s (scripts 80 to 41 files, 613 to 317 KB); Dossier 5.17 to 3.30 s (699 to 358 KB); Chart 5.41 to 3.93 s (696 to 431 KB); Compare 5.07 to 5.61 s (scripts 588 to 244 KB; its load waits on `/api/compare`, which varies with the provider). A first in-app visit to a page outside the warmed set costs one 5 to 12 KB module (about 0.2 to 0.3 s on this network). After 40 route changes: 7,980 nodes before and after, 104 listeners before and after, heap 4.7 to 5.5 MB; freeze and resume: the chart drew afterwards, no errors.

**Tests:** `tests/test_v2_performance.py` (6); `tests/test_frontend_switch.py` and `tests/test_v2_checklist.py` updated for the new preload list and page map.

**Remaining bottlenecks:** a first visit on a slow phone is still bandwidth-bound (300 to 430 KB of unminified modules and CSS; minifying would need a build step v2 does not have); the Dossier snapshot (`/api/ticker`, about 120 KB) dominates warm phone loads; the provider's overnight rate limits make server times vary by seconds. Not measured on a physical phone.
